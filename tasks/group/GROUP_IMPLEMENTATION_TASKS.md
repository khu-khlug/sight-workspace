# 그룹 시스템 재구현 태스크

## 개요

이 문서는 기존 Laravel 그룹 시스템을 새로운 서버로 대체 구현할 때 필요한 작업을 큰 단위로 나누고, 권장 진행 순서를 정리한 것입니다.

각 Phase는 이전 Phase의 완료를 전제로 합니다.

### 기존 시스템과의 주요 차이점

새 시스템에서는 **HTML WYSIWYG 에디터(CKEditor)를 Markdown 에디터로 전면 교체**합니다. 이 결정은 아래 Phase들에 걸쳐 영향을 줍니다.

| 영향 범위 | 기존 | 변경 |
|-----------|------|------|
| `group_record.content` 저장 형식 (Phase 1) | HTML 문자열 | Markdown 문자열 |
| 콘텐츠 처리 파이프라인 (Phase 2) | HTML XSS 필터 | Markdown → HTML 변환 + HTML sanitize |
| `Record::content()` (Phase 3) | HTML 필터 후 반환 | Markdown 렌더링 후 반환 |
| 기록 작성/수정 UI (Phase 5) | CKEditor (WYSIWYG) | 좌측 작성·우측 렌더링 split-pane 에디터 |

## Phase 1. 데이터베이스 설계 및 마이그레이션

> 참고: `GROUP_DATA_SCHEMA.md`

모든 기능의 토대가 되는 단계입니다. 스키마가 확정되기 전까지 이후 작업이 불가능합니다.

### 태스크

- **1-1. 그룹 핵심 테이블 생성**
  - `group`, `group_member`, `group_list`, `group_card`, `group_record`, `group_log`
  - 마이그레이션 이후 직접 추가된 컬럼 포함: `group.interest`, `group_card.incharge`, `group_card.sort_record`

- **1-2. 그룹 확장 테이블 생성**
  - `group_bookmark`, `group_seminar`, `group_seminar_term`, `group_record_saved`

- **1-3. 공통 의존 테이블 확인/생성**
  - `sequence` (전역 ID 채번용, 별도 설계 검토 필요)
  - `files` (첨부파일/커버 이미지 공용)
  - `autosave` (기록 자동 저장)
  - `notification`, `expoint_log` (알림/포인트 레거시 기록용)

- **1-4. 연관 테이블 확인**
  - `members` (회원), `members_interest` (관심 분야)
  - `special_dept`, `special_dept_member`, `special_dept_group` (특수 조직)
  - `ideacloud` (아이디어클라우드 연동)

### 주요 설계 결정 사항

- **전역 ID 채번 방식**: 기존 시스템은 `sequence` 테이블 단일 auto-increment를 모든 엔티티가 공유합니다. 새 시스템에서 동일 방식을 유지할지, 테이블별 auto-increment로 분리할지 결정이 필요합니다. (기존 방식을 바꾸면 아카이브된 카드의 `list = group.id` 처리 방식도 함께 재설계해야 합니다.)
- **카운터 캐시**: `count_member`, `count_card`, `count_record` 등은 정규화 대신 직접 증감하는 방식입니다. ORM 레벨에서 트랜잭션으로 보장할지, 이벤트 훅으로 처리할지 결정이 필요합니다.
- **`group_record.content` 저장 형식**: 새 시스템에서는 Markdown 원문을 저장합니다. 컬럼 타입(`longtext`)은 동일하게 유지해도 무방하나, 기존 HTML 데이터와 혼용되지 않도록 마이그레이션 시점과 전환 전략을 명확히 합니다.

## Phase 2. 공통 인프라 구현

> 참고: `GROUP_SYSTEM.md`

그룹 기능 전반에서 호출되므로 기능 구현보다 먼저 완성되어야 합니다.

### 태스크

- **2-1. 전역 ID 채번 시스템**
  - `sequence` 테이블 insert 방식 또는 대체 UUID/Snowflake 전략 구현
  - 모든 엔티티 생성 코드에서 일관되게 사용

- **2-2. 알림 시스템**
  - 알림 발송 및 저장 로직 구현 (같은 서버 내 직접 처리)
  - `manager` (운영진 전체), `broadcast` (재·휴학 전체) 수신자 타입 처리
  - `secret` 플래그(발신자 익명 처리) 지원

- **2-3. ExPoint 시스템**
  - `members.expoint` 직접 업데이트 로직
  - `expoint_log` 이력 기록 로직
  - 대상(`$to`) 미지정 시 로그인 회원에게 적용

- **2-4. Markdown 렌더러 및 콘텐츠 파이프라인** *(기존 HTML XSS 필터 대체)*
  - Markdown → HTML 변환 라이브러리 선정 및 통합
  - 변환된 HTML에 대한 sanitize 처리: `<script>`, 이벤트 핸들러(`on*`), `javascript:` / `data:` URI 차단
  - URL 자동 링크 변환은 Markdown 파서가 처리하므로 별도 구현 불필요
  - 기존 `Controller::filterHTML()` 로직은 **사용하지 않음**

## Phase 3. 도메인 모델 구현

> 참고: `GROUP_BUSINESS_RULES.md`, `GROUP_DATA_SCHEMA.md`

컨트롤러에서 직접 호출하는 비즈니스 로직의 핵심입니다. 권한 체계와 상태 전이 로직이 모두 이 계층에 있습니다.

### 태스크

- **3-1. Group 도메인**
  - 열람 권한 체크: grade 기반 + special_dept 이중 검증 (→ `BUSINESS_RULES` 2장)
  - 쓰기 권한 체크: 멤버 여부 확인, 고객센터 예외 처리
  - 활동 갱신: `changed_at` 갱신 + 중단 → 진행 자동 복귀
  - 멤버 관리: 추가, 탈퇴(그룹장 탈퇴 불가 조건), 그룹장 위임
  - 리스트/카드/아카이브 카드 조회
  - 활동 로그 기록 및 조회 (고객센터 열람 차단)
  - 세미나 등록 정보, 즐겨찾기 여부, 소속 여부 확인

- **3-2. List 도메인**
  - 활성 카드 조회 (아카이브 제외, 정렬 적용)

- **3-3. Card 도메인**
  - 레이블 비트마스크 토글 (8색 독립 on/off)
  - 소속 그룹 역추적 (아카이브 카드의 경우 list가 group ID로 변경되어 있음)
  - 기록 조회 (카드별 정렬 방향 적용)
  - 이어받기 연결 파싱
  - 커버 이미지 조회

- **3-4. Record 도메인**
  - 내용 렌더링: Markdown → HTML 변환 후 반환 (Phase 2-4 의존)
  - 수정용 원문 반환
  - 첨부 파일 조회

- **3-5. User 도메인 (그룹 관련)**
  - 운영진/교류 회원 여부 확인
  - 참여 그룹 목록, 즐겨찾기 목록 (특수 그룹 자동 포함)
  - 기록 보관함
  - 특수 조직 소속 확인

## Phase 4. 그룹 관리 API

> 참고: `GROUP_BUSINESS_RULES.md` — 2~5장

그룹 자체의 생성·조회·수정·상태 변경과 멤버 관리를 담당합니다.

### 태스크

- **4-1. 그룹 목록 및 검색**
  - 내 그룹 / 타입별(프로그램·연구·문서화) / 상태별(진행·성공) 목록
  - 관심 분야별, 조직별 필터링
  - 키워드 검색 (제목·목적·기술 스택)
  - 회원별 참여 현황 (참여/미참여 분류)

- **4-2. 그룹 상세 조회**
  - grade + special_dept 권한 체크
  - Discord 채널 정보 연동 (Phase 7 이후 완성 가능, 우선 null 처리)

- **4-3. 그룹 생성 및 수정**
  - 카테고리·grade 유효값 검증, 아이디어클라우드 연동, +50 exp
  - 수정: 그룹장 권한, 종료 상태 차단

- **4-4. 그룹 상태 변경**
  - 상태 전이 규칙 (suspend는 운영진만), ExPoint 변동
  - 자동 중단 로직 (Phase 7 스케줄러와 연결)

- **4-5. 포트폴리오 및 즐겨찾기**
  - 포트폴리오 발행 토글, ExPoint ±10
  - 즐겨찾기 토글 (특수 그룹 제외)

- **4-6. 멤버 관리**
  - 참여: allow_join 체크, +40 exp
  - 탈퇴: 그룹장 탈퇴 불가 조건, -40 exp
  - 내보내기: 그룹장 권한, -40 exp
  - 그룹장 위임
  - 멤버 목록 조회
  - 활동 로그 조회

## Phase 5. 칸반 보드 기능 (리스트 · 카드 · 기록)

> 참고: `GROUP_BUSINESS_RULES.md` — 6~9장

그룹 시스템의 핵심 기능입니다. 리스트 → 카드 → 기록 순으로 의존 관계가 있습니다.

### 태스크

- **5-1. 리스트 CRUD**
  - 추가, 수정(이름/설명), 삭제(카드 잔존 시 차단), 순서 재정렬

- **5-2. 카드 기본 CRUD**
  - 추가: ExPoint +1, 멤버 알림
  - 수정: 이름/설명
  - 순서 변경: 리스트 간 이동 포함
  - 카드 상세 조회 (고객센터 작성자 제한)
  - 전체 카드 목록 조회

- **5-3. 카드 상태 관리**
  - 아카이브(소프트 삭제): ExPoint -1
  - 복구: ExPoint +1
  - 활성화/비활성화 토글

- **5-4. 카드 부가 기능**
  - 담당자 지정/해제 (전·후 담당자 알림)
  - 리스트 간 이동
  - 이어받기 설정 (기록 5개 제한)
  - 레이블 토글 (8색)
  - 기록 정렬 방향 변경
  - 포트폴리오 포함 토글
  - 커버 이미지 업로드/제거

- **5-5. 기록 CRUD**
  - 추가: 파일/이미지 첨부, 기록 작성자에게 +2 exp
  - 수정: 작성자 본인만 (특수 그룹 9477 예외)
  - 아카이브(소프트 삭제): 기록 작성자에게 -2 exp
  - 복구: 복구한 회원에게 +2 exp

- **5-6. 기록 부가 기능**
  - 보관함: 보관/해제 토글, 보관 기록 목록
  - 기록 이동 (같은 그룹 내 카드 간)
  - 외부 임베드용 반환 (권한 체크 포함)
  - 포트폴리오 포함 토글

- **5-7. 검색 및 아카이브 뷰**
  - 그룹 내 검색: 카드명 또는 기록 내용 키워드
  - 아카이브된 카드 목록 조회

- **5-8. Markdown 에디터 컴포넌트** *(신규)*
  - 좌측 Markdown 작성 영역 + 우측 실시간 렌더링 영역(split-pane) UI
  - 기록 작성/수정 양쪽에서 공통 사용
  - 이미지/파일 첨부: 드래그앤드롭 또는 버튼 업로드 후 Markdown 이미지 문법 삽입
  - 자동 저장 연동
  - 서버/클라이언트 렌더 결과 일치 보장

## Phase 6. 포트폴리오 및 세미나

> 참고: `GROUP_BUSINESS_RULES.md` — 10~11장

Phase 4~5가 완료된 후 진행 가능합니다. 포트폴리오는 그룹·카드·기록의 `portfolio` 플래그, 세미나는 별도 기수 관리 테이블을 사용합니다.

### 태스크

- **6-1. 포트폴리오**
  - 발행된 그룹 목록 (페이지네이션)
  - 그룹 포트폴리오 페이지 (포함 카드/기록 표시)
  - 포트폴리오 카드 상세 조회

- **6-2. 세미나 기수 관리**
  - 기수 목록 조회
  - 기수 추가 (운영진 알림)
  - 기수 삭제 (운영진만, 전년도 불가)
  - 접수 상태 변경 (접수 전→접수 중→마감→재오픈), 방송 알림 + Slack

- **6-3. 세미나 세션 관리**
  - 기수별 등록 그룹 및 참여 멤버 목록
  - 세션 등록/취소 토글 (그룹장, 접수 중 기간만), ±150 exp
  - 운영진 강제 제거: 그룹 멤버 전체 -150 exp
  - 보고서 제출·취소에도 세미나 발표와 동일한 +150/-150 exp 적용

## Phase 7. 외부 연동 및 자동화

> 참고: `GROUP_SYSTEM.md` — 5~6번 섹션

기능 자체는 Phase 4~6에서 null 처리로 우선 통과시키고, 이 Phase에서 실제 연동을 완성합니다.

### 태스크

- **7-1. 자동 중단 스케줄러**
  - 50일 미활동 그룹 자동 중단 처리
  - 주기적 실행 등록 (cron 또는 프레임워크 스케줄러)
  - 대상 그룹 멤버 전체에 알림 발송

- **7-2. Discord 연동**
  - 그룹별 Discord 채널 URL 조회
  - 사용자별 Discord 채널 참여 여부 조회
  - 두 API 모두 실패 시 graceful 처리 (기능 미표시)

- **7-3. Slack 기록 추가 연동**
  - Slack 봇에서 특정 회원 명의로 기록 추가하는 엔드포인트
  - 인증 방식 설계 (기존: User-Agent 헤더 검증)

- **7-4. Discord 알림 연동**
  - 세미나 접수 시작/마감 시 Discord 채널 알림 발송 (레거시 Slack 채널 알림 대체)

## Phase 의존 관계 요약

```
Phase 1 (DB 스키마)
  └── Phase 2 (공통 인프라)
        └── Phase 3 (도메인 모델)
              ├── Phase 4 (그룹 관리 API)
              │     └── Phase 5 (칸반 보드)
              │           └── Phase 6 (포트폴리오/세미나)
              │                 └── Phase 7 (외부 연동)
              └── Phase 7 (일부 독립적으로 진행 가능)
```

Phase 4~7은 Phase 3 이후라면 병렬 진행도 가능합니다. 단, Phase 6은 Phase 5의 `portfolio` 플래그 처리가 완료되어야 의미 있습니다.

Phase 5-8(Markdown 에디터)은 Phase 2-4(Markdown 파이프라인)와 Phase 5-5(기록 CRUD 엔드포인트)가 모두 완료된 후 통합합니다.

## 특수 케이스 및 구현 주의사항

특수 그룹 규칙, 상태 전이, 멤버 관리 등 비즈니스 규칙 상세 → [GROUP_BUSINESS_RULES.md](./GROUP_BUSINESS_RULES.md) 참조

아래는 **새 시스템 고유의 구현 주의사항**입니다:

| 항목 | 내용 |
|------|------|
| 아카이브 카드의 `list` | 원래 list ID → group ID 로 변경됨. 전역 ID 채번 방식을 바꿀 경우 재설계 필요 |
| 카운터 캐시 | `count_*` 컬럼은 insert/delete 시 수동 ±1 동기화 필요. ORM/이벤트 훅으로 보장할지 결정 |
| `group_record.content` 형식 | 새 시스템은 Markdown 저장. 표시 시 서버에서 Markdown → HTML 변환 후 반환 |
