# 지원 신청 Frontend

## 작업 개요

회원이 지원 신청을 등록하고 모든 회원이 신청과 댓글을 확인할 수 있는 지원 신청 화면을 제공한다. `/support`에서 지원 신청을 확인하고, 신규 등록·상세 확인·첫 댓글 전 신청자 수정·운영진 삭제·신청자 또는 운영진 댓글 작성을 완료할 수 있으면 작업이 완료된다.

## 사용자와 목표

- 회원은 동아리 활동에 필요한 서버 공간, 서브 도메인, 하드웨어, 도서 또는 기타 지원을 요청하고 모든 회원의 지원 신청과 댓글을 확인하며, 자신이 등록한 지원 신청에 댓글을 남긴다.
- 운영진은 모든 지원 신청을 확인하고 댓글로 필요한 추가 정보나 처리 상황을 전달한다.

## 사용자 경험 계약

- `/support`는 지원 신청 목록 진입점이다. 모든 회원에게 모든 신청을 최신 등록 순으로 보여준다.
- `/support/new`에서 카테고리, 제목 및 내용을 입력해 지원 신청을 등록한다. 등록 성공 후 생성된 지원 신청의 상세 화면으로 이동한다.
- `/support/:supportRequestId`는 신청 내용, 신청자, 등록 시각과 시간순 댓글을 모든 회원에게 보여준다. 존재하지 않는 신청은 접근할 수 없음을 알린다.
- 신청자는 댓글이 하나도 없는 상세 화면에서만 수정할 수 있다. 운영진은 댓글 유무와 관계없이 삭제할 수 있으며, 삭제는 확인 후 목록으로 이동한다.
- 첫 댓글이 생성된 상세 화면에서는 신청자에게 수정 행동을 제공하지 않고, 신청 내용이 더 이상 수정될 수 없음을 구분해 알린다. 운영진에게는 삭제 행동을 계속 제공한다.
- 신청자와 운영진은 상세 화면에서 댓글을 등록할 수 있다. 신청자가 아니고 운영진도 아닌 회원에게는 댓글 입력과 등록 행동을 제공하지 않는다. 댓글 등록 성공 후 새 댓글이 시간순 목록에 나타난다. 댓글 등록에 따른 사이트 내 알림과, 신청자가 Discord 연동 상태일 때 운영진 댓글에 따른 Discord DM은 Backend가 자동 처리하며, Frontend는 알림 발송 여부를 설정하거나 재전송하지 않는다.
- 지원 신청 등록·수정·삭제·댓글 등록 요청이 처리 중이면 해당 행동의 버튼을 비활성화한다. 관련 공통 버튼 컴포넌트를 사용하면 그 컴포넌트가 제공하는 비활성화 설정을 따른다. 요청 결과가 확정되면 버튼을 다시 사용할 수 있으며, 요청이 실패하면 작성한 입력을 유지한 채 다시 시도할 수 있다. 지원 신청과 댓글 등록 요청은 멱등하게 처리하지 않는다.

## 허용 및 제한 정책

### 지원 신청 열람

- 주체: 로그인한 모든 회원
- 조건: 지원 신청 상세를 열려고 함
- 행동: 지원 신청과 댓글 조회
- 판정: 허용
- 허용 예외: 없음
- 사용자에게 보이는 처리: 모든 지원 신청의 내용, 신청자 정보와 댓글을 목록과 상세에서 표시한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 존재하지 않는 지원 신청은 목록으로 돌아갈 수 있도록 안내한다.

### 지원 신청 수정

- 주체: 지원 신청을 등록한 회원
- 조건: 자신의 지원 신청에 댓글이 하나도 없음
- 행동: 제목, 내용, 카테고리 수정
- 판정: 조건부 허용
- 허용 예외: 없음
- 사용자에게 보이는 처리: 첫 댓글 전 신청자에게만 수정 행동을 표시한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 첫 댓글이 등록되면 수정할 수 없다는 이유를 표시하고 추가 정보는 댓글로 남기도록 안내한다.

### 지원 신청 삭제

- 주체: 운영진
- 조건: 지원 신청 상세를 열람함
- 행동: 모든 지원 신청 삭제
- 판정: 허용
- 허용 예외: 없음
- 사용자에게 보이는 처리: 모든 상세 화면에 삭제 행동을 표시하고, 삭제 전에는 지원 신청과 댓글이 함께 영구 삭제됨을 확인한다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 삭제 뒤에는 복구할 수 없다.

### 처리 중인 요청의 재실행

- 주체: 지원 신청 등록, 수정, 삭제 또는 댓글 등록을 시도한 회원 또는 운영진
- 조건: 같은 행동의 이전 요청 결과가 아직 확정되지 않음
- 행동: 같은 행동의 버튼을 다시 클릭
- 판정: 금지
- 허용 예외: 없음
- 사용자에게 보이는 처리: 해당 행동의 버튼을 비활성화한다. 관련 공통 버튼 컴포넌트를 사용하면 그 컴포넌트가 제공하는 비활성화 설정을 따른다.
- 보장 계층: Frontend
- 안내 및 회복: 요청 결과가 확정되면 버튼을 다시 사용할 수 있다. 요청이 실패하면 입력을 유지한 채 다시 시도할 수 있다.

### 댓글 등록

- 주체: 지원 신청을 등록한 회원 또는 운영진
- 조건: 신청자가 자신의 지원 신청을 열람하거나 운영진이 지원 신청 상세를 열람하고 댓글을 작성하려고 함
- 행동: 지원 신청 댓글 등록
- 판정: 조건부 허용
- 허용 예외: 운영진은 모든 지원 신청에 댓글을 등록할 수 있다.
- 사용자에게 보이는 처리: 신청자와 운영진에게만 댓글 입력과 등록 결과를 보여주고, 신청자가 아닌 운영진이 아닌 회원에게는 댓글 입력과 등록 행동을 표시하지 않는다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 요청 실패 시 입력을 유지하고 다시 등록할 수 있다.

## 입력 및 복구

- 신규 및 수정 입력은 카테고리 하나, 공백만으로 구성되지 않은 제목과 내용만 허용한다. 카테고리는 서버 공간, 서브 도메인, 하드웨어, 도서, 기타를 사람이 이해할 수 있는 이름으로 표시한다.
- 등록과 수정은 서버 요청 전 입력 오류를 표시하고, 서버 validation 오류도 해당 입력과 함께 표시한다.
- 등록 또는 댓글 작성 실패 시 제목, 내용, 카테고리 및 댓글 입력을 유지한다. 삭제 실패 시 상세 화면과 신청 내용은 유지한다.
- 지원 신청 또는 댓글 등록을 반복 요청하면 각 요청은 별도 생성으로 처리될 수 있다.

## 데이터 및 연동

- 지원 신청과 댓글의 source of truth는 `tasks/completed/support-request-backend.md`가 정의하는 `/support-requests` API다.
- 목록은 `GET /support-requests`, 상세는 `GET /support-requests/{supportRequestId}`, 등록은 `POST /support-requests`, 수정과 삭제는 해당 item의 `PUT`과 `DELETE`, 댓글 등록은 `POST /support-requests/{supportRequestId}/comments`를 사용한다.
- 목록, 상세, 수정 가능 여부와 댓글 목록은 요청 성공 뒤 API 응답으로 즉시 갱신한다. 수정이 `409 Conflict`로 거절되면 상세를 다시 조회해 첫 댓글 생성 상태를 반영한다.
- Discord 운영 채널 메시지와 DM, 사이트 내 알림은 Backend의 동작이며 Frontend는 전달 성공 여부를 표시하거나 재전송하지 않는다.
- Backend API 배포 후 `/support`를 새 화면으로 제공한다.

## 사용자 보호 및 개인정보

- 지원 신청 제목·내용·댓글과 신청자 이름은 모든 로그인한 회원에게 표시한다. 목록, URL, 브라우저 저장소 및 오류 화면을 통해 인증되지 않은 사람에게 지원 신청 내용을 노출하지 않는다.
- 삭제는 운영진만 확인 후 실행할 수 있고, 댓글이 있으면 함께 영구 삭제된다.
- Discord 알림은 Backend가 처리하며, Frontend는 Discord 계정 ID나 Bot token을 조회·저장·전송하지 않는다.

## 접근성 및 사용 환경

- 카테고리 선택, 등록·수정·삭제·댓글 작성은 키보드로 모두 조작할 수 있고 각 입력에 label을 제공한다.
- 첫 댓글 후 신청자는 수정할 수 없고 운영진은 삭제할 수 있는 상태와 요청 처리 상태는 색상이나 아이콘만으로 전달하지 않고 텍스트로도 제공한다.
- 긴 제목·내용·댓글과 좁은 화면에서 목록, 상세 및 입력이 잘리지 않고 읽고 작성할 수 있어야 한다.

## 검증

- 일반 회원이 다섯 카테고리 각각으로 등록하고 모든 회원의 목록·상세·댓글을 확인하는 흐름을 확인한다.
- 운영진이 전체 목록과 다른 회원의 상세·댓글을 확인하고 댓글을 등록하는 흐름을 확인한다.
- 첫 댓글 전 신청자의 수정과 운영진의 다른 회원 신청 삭제가 보이고 동작하며, 첫 댓글 뒤에는 신청자 수정 행동만 사라지고 운영진 삭제 행동은 유지되며, 신청자 수정의 `409` 응답 후 최신 상태로 갱신되는지 확인한다.
- 일반 회원이 자신의 지원 신청에서는 댓글 입력과 등록 행동을 확인하고, 다른 회원의 URL에 직접 접근하면 신청 내용과 댓글은 확인할 수 있으나 댓글 입력과 등록 행동은 표시되지 않는지 확인한다.
- 빈 제목·내용, 카테고리 미선택, 등록·댓글 요청 실패에서 오류가 이해 가능하고 입력이 유지되는지 확인한다.
- 느린 네트워크에서 같은 등록 또는 댓글 제출을 반복하면 각 요청이 별도 신청 또는 댓글로 생성될 수 있음을 확인한다.
- 키보드만으로 카테고리 선택, 등록, 댓글 작성, 삭제 확인을 수행하고 좁은 화면과 긴 내용에서 상태 안내를 확인한다.

## 비목표

- 지원 신청 승인, 반려, 완료 및 자원 배정 UI를 제공하지 않는다.
- 댓글 수정·삭제, Discord 또는 사이트 내 알림의 열람·재전송 UI는 제공하지 않는다.
