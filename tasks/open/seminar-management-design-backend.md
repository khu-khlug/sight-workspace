# 세미나 중심 생성·관리 전환 설계

## 작업 개요

현재는 세미나 전용 생성·관리 페이지와 폼이 없어 일정에서 세미나를 추가하도록 되어 있으며, 세미나 생성·수정·삭제 API도 `/schedules/big-seminar` 아래에 있다. 접수 중인 세미나 조회 API의 경로를 기존 세미나 API와 맞추는 과정에서 이 구조가 현재 관리 방식에 따른 것임을 확인했다. 향후에는 세미나 생성·관리 폼에서 세미나를 추가하면 일정에도 자동으로 반영되는 구조로 전환해야 하므로, 현재 일정 중심 API를 최종 구조로 굳히지 않고 후속 작업을 추적하기 위해 이 문서를 만들었다.

현재 일정에서 세미나를 추가하는 흐름을 세미나 생성·관리 중심의 흐름으로 전환하기 위한 후속 설계 TODO다. 세미나를 생성하면 연결된 일정도 함께 생성되도록 한다.

관련 저장소는 `sight-spring-backend`와 `sight-frontend`다. 이 Task의 완료 결과는 세미나와 일정의 생명주기, HTTP API 계약, 기존 경로의 호환성 및 저장소별 구현 범위를 확정한 설계 문서다. 이 Task에서는 코드를 변경하거나 기존 API를 폐기하지 않는다.

- Backend: 세미나 중심의 생성·수정·삭제와 연결 일정의 연동 계약을 설계한다.
- Frontend: 확정된 API 계약을 기준으로 세미나 생성·관리 폼의 후속 Frontend Task를 작성한다.
- 의존 관계: 공통 API 계약을 확정한 뒤 각 저장소의 구현 Task로 이어간다.

## 비즈니스 동작

이 Task에서 실제 동작 변경은 없다. 후속 구현을 위한 설계는 다음 요구사항을 충족해야 한다.

- 운영진이 세미나를 생성·관리하며, 세미나를 생성하면 일정에도 자동으로 추가된다.
- 세미나와 연결 일정의 수정·삭제 연동 기준을 정의한다.
- 세미나 생성과 일정 생성 도중 실패하거나 요청을 재시도해도 한쪽만 생성되거나 일정이 중복 생성되지 않도록 계약을 정의한다.
- 기존 세미나와 일정의 연결, 활동보고 및 출석 기록의 처리 기준을 설계에 포함한다.
- 활동보고서 제출과 세미나 발표 등록의 접수 기간은 [그룹 정책](../../policy/그룹/POLICY.md)을 유지한다.

## HTTP API 계약

변경 없음. 이 Task는 설계 작업이며 새 endpoint를 도입하거나 기존 endpoint를 변경하지 않는다.

다음 기존 계약을 기준으로 세미나 중심 API와 호환성 전환 방안을 설계한다.

- [세미나 일정 생성](../../sight-spring-backend/docs/plans/schedule/create-big-seminar-schedule.md): `POST /schedules/big-seminar`
- [세미나 일정 수정](../../sight-spring-backend/docs/plans/schedule/update-big-seminar-schedule.md): `PATCH /schedules/big-seminar/{scheduleId}`
- [세미나 일정 삭제](../../sight-spring-backend/docs/plans/schedule/delete-big-seminar-schedule.md): `DELETE /schedules/big-seminar/{scheduleId}`
- [일정 카테고리 변경](../../sight-spring-backend/docs/plans/schedule/update-schedule-category.md): 세미나 전환에 따른 생성·삭제 연동
- [접수 중인 세미나 조회](../../sight-spring-backend/docs/plans/group/exposure/open-seminar-get.md): 세미나와 일정에 기반한 접수 대상 조회

후속 구현 전에 새 계약의 method·path·식별자·요청·응답·권한·오류·중복 요청 처리와 기존 경로의 유지·전환 범위를 확정한다.

## 데이터베이스 계약

변경 없음. 설계에서 세미나와 일정의 연결, 생성의 원자성, 수정·삭제 연동 및 기존 데이터의 호환성을 정의한다. 데이터 구조 변경이 필요한 경우 migration·rollback 계약을 후속 구현 Task에 포함한다.

## 외부 시스템 계약

변경 없음.

## 보안 및 개인정보

변경 없음. 세미나 생성·수정·삭제의 운영진 권한을 유지하는 것을 설계 요구사항으로 한다.

## 비가역적 부작용 및 운영 영향

변경 없음. 이 Task에서는 데이터 삭제·변경, 알림 발송 및 외부 호출을 수행하지 않는다. 후속 설계에는 세미나·일정 삭제가 기존 활동보고와 출석 기록에 미치는 영향을 포함한다.

## 호환성 및 배포

변경 없음. 현재 일정 기반 생성·관리 API는 이 Task로 변경되지 않는다.

후속 설계는 기존 API 사용처, 기존 세미나·일정 데이터, Backend 제공과 Frontend 전환의 순서, 기존 경로의 호환성 및 rollback 범위를 포함한다.

## 검증

코드 테스트나 브라우저 조작이 아닌 설계 문서 검토로 완료 여부를 판단한다.

- 세미나 생성 성공 시 일정에도 한 번만 추가되는 계약과 부분 실패·재시도 처리가 명시되어 있다.
- 세미나 수정·삭제와 일정의 연동, 기존 활동보고·출석 기록의 처리 기준이 명시되어 있다.
- 생성·수정·삭제는 운영진만 수행할 수 있는 계약이다.
- 접수 기간 판단이 그룹 정책과 일치한다.
- 기존 경로와 데이터의 호환성, 배포·복구 순서가 명시되어 있다.
- 확정된 공통 API 계약을 참조하는 Backend·Frontend 구현 Task에 저장소별 범위와 의존 관계가 정리되어 있다.

## 비목표

- 이 Task에서 세미나 관리 기능과 폼을 직접 구현하는 것
- 설계 확정 전에 기존 endpoint를 변경·폐기하는 것
- 활동보고 접수 기간이나 경험치 정책을 변경하는 것
