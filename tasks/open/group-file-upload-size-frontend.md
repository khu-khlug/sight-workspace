# 그룹 파일 업로드 크기 서명 연동

## 작업 개요

활동보고 파일, 카드 커버 이미지, 기록·임시저장의 신규 첨부 파일을 크기에 서명한 R2 업로드 주소로 올린다. 프런트가 업로드할 파일의 바이트 크기를 백엔드에 보내고, 받은 주소로 같은 파일을 직접 전송한다. 20 MiB까지 업로드할 수 있고, 실패한 파일은 다시 시도하거나 교체할 수 있어야 한다.

## 사용자와 목표

- 활동보고를 제출·수정하는 그룹장은 선택한 파일을 올려 보고서에 연결한다.
- 카드 커버나 기록을 편집할 수 있는 회원은 이미지를 커버로 지정하거나 새 파일을 기록에 첨부한다. 기록을 임시저장한 경우에도 업로드 결과를 확인할 수 있다.

## 사용자 경험 계약

- 선택, 드래그 앤 드롭, 붙여넣기 등 각 화면의 기존 파일 입력 방식에 같은 크기 제한을 적용한다.
- 활동보고와 카드 커버는 파일을 올린 뒤 기존 제출·수정·지정 요청을 보낸다. 새 파일을 올리는 데 실패하면 기존 보고서와 커버를 유지한다.
- 기록·임시저장은 저장 응답으로 받은 신규 첨부별 주소로 파일을 올린다. PUT에 성공한 파일만 [기록 첨부 파일 업로드 완료 API](../../sight-spring-backend/docs/plans/group/edit-window/group-record-files-uploaded.md)에 전달한다. 여러 첨부 중 일부가 실패하면 실패한 파일만 다시 시도할 수 있게 한다.

## 허용 및 제한 정책

### 신규 업로드의 파일 크기

- 주체: 활동보고 파일, 카드 커버 이미지 또는 기록 첨부를 업로드할 권한이 있는 회원
- 조건: 실제로 전송할 파일의 바이트 크기가 20 MiB 이하이며 R2에 보내는 파일 크기가 업로드 주소에 서명된 크기와 일치함
- 행동: 새 업로드 주소를 발급받아 파일을 업로드
- 판정: 조건부 허용
- 허용 예외: 없음
- 사용자에게 보이는 처리: 한도를 넘는 파일은 주소를 요청하기 전에 차단한다. 발급이나 업로드가 거부된 파일은 업로드 완료로 표시하지 않는다.
- 보장 계층: Frontend와 Backend
- 안내 및 회복: 크기 제한을 알려주고 허용 크기의 파일을 다시 선택할 수 있게 한다. 발급 후 파일이 바뀌면 현재 파일에 맞는 새 주소로 다시 시도할 수 있다.

## 입력 및 복구

- 실제로 PUT할 `File`의 `size`를 바이트 단위로 보낸다. 화면 표시용으로 반올림한 값은 사용하지 않는다. 업로드 전 이미지 변환 등이 있다면 변환이 끝난 파일의 크기를 사용한다.
- 파일을 PUT 요청 본문으로 그대로 보낸다. 브라우저가 본문 길이로 `Content-Length`를 설정하므로 프런트에서 이 헤더를 직접 지정하거나 파일을 `FormData`로 감싸지 않는다.
- 링크 만료나 크기 불일치로 실패하면 작성 내용과 사용할 수 있는 파일 선택을 유지한다. 새로 선택한 파일이나 변환한 파일은 현재 바이트 크기로 주소를 다시 발급받는다. 기록에서 만료된 링크는 기존 기록·임시저장 첨부 흐름으로 실패한 파일을 다시 추가해 발급받는다.

## 데이터 및 연동

- [활동보고 업로드 링크 발급](../../sight-spring-backend/docs/plans/group/exposure/activity-report-upload-link.md)과 [카드 커버 이미지 업로드 링크 발급](../../sight-spring-backend/docs/plans/group/card-window/group-card-cover-image-upload-link.md)의 `size`에 실제 전송 파일의 바이트 크기를 보낸다.
- [그룹 기록 첨부 계약](../../sight-spring-backend/docs/plans/group/global.md#기록-첨부-파일)의 기존 `files[].size`를 사용한다. 기록 작성·수정·임시저장에서 신규 첨부의 크기가 발급 주소에 서명되며, 기존 파일을 `fileId`로 다시 연결할 때는 기존 첨부 계약을 따른다.
- 발급 요청의 크기를 검증하고 `Content-Length`에 서명하는 백엔드 API와 연동한다. 각 기능의 프런트는 해당 API가 배포된 환경에서 공개한다.

## 사용자 보호 및 개인정보

- 임시 PUT 주소는 해당 파일의 업로드와 재시도에만 사용한다. 기록 본문이나 공유할 다운로드 주소에는 기존 영구 파일 주소를 사용한다.

## 검증

- 활동보고의 PDF, 카드 커버의 PNG 또는 JPEG, 기록·임시저장의 일반 첨부를 브라우저로 올린다. 발급 요청의 바이트 크기가 실제 PUT 본문 크기와 일치하고, 각 화면에서 제출·지정·첨부를 완료할 수 있는지 확인한다.
- 정확히 20 MiB인 파일은 업로드할 수 있고, 20 MiB보다 1바이트 큰 파일은 링크 발급 전 화면에서 거부되는지 확인한다. 지원하는 브라우저와 파일 입력 방식으로 검증한다.
- 발급 후 다른 크기의 파일로 교체하거나 주소가 만료된 경우, 이전 주소로 성공 처리하지 않고 작성 내용과 기존 파일을 보존한 채 다시 시도할 수 있는지 확인한다.
- 기록 첨부를 여러 개 올리다 한 건만 실패할 때, 성공한 첨부는 보존하고 실패한 첨부만 다시 시도할 수 있는지 확인한다.
