# 그룹 페이지 용어 정의

2026-10-09 기준. 그룹 페이지의 문서, 설계 논의, 코드 리뷰에서 사용하는 용어를 정리한다. 프런트엔드와 백엔드에서 같은 개념을 같은 이름으로 표현하기 위한 기준이다.

비즈니스 정책의 공통 개념은 [정책 용어 사전](../../../policy/GLOSSARY.md)을 참고한다. 그룹 페이지에서는 특정 그룹에 참여하는 회원을 그룹 멤버로 부른다. 이 문서는 그룹 페이지의 화면과 구현에서 필요한 개념을 정의하며, API 경로나 데이터베이스 스키마를 확정하는 문서는 아니다. 아래 코드 식별자는 현재 프런트엔드 구현을 기준으로 한다.

## 1. 그룹과 구성원

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 그룹 | 회원이 함께 동아리 활동을 수행하고 관리하는 협업 단위. | `group`, `groupId` |
| 그룹 페이지 | 특정 그룹의 정보, 칸반 보드, 기록, 채팅방과 설정 등을 다루는 상세 페이지. 문서에서 그룹 상세 페이지와 같은 뜻으로 사용한다. | `GroupDetailContainer` |
| 그룹 멤버 | 특정 그룹에 현재 참여하고 있는 회원. 화면에서는 멤버로 표시한다. | `isMember`, 멤버 탭 |
| 그룹장 | 해당 그룹의 대표·관리 역할을 맡은 그룹 멤버. 운영진과 구분한다. | `leaderUserId` |
| 운영진 | 동아리 운영을 담당하는 구성원. 특정 그룹의 그룹장 여부와 별개의 역할이다. | `isManager` |
| 그룹 카테고리 | 그룹의 활동 목적과 운영 성격을 구분하는 분류. | 스터디, 프로젝트, 문서화, 운영, 교육, 프로그램 |
| 그룹 상태 | 그룹이 진행 중인지, 중단되었는지 또는 종료되었는지를 나타내는 분류. | 진행 중, 중단, 종료(성공), 종료(실패) |
| 공개 범위 | 그룹의 정보를 어느 범위의 사람이 조회할 수 있는지를 나타내는 설정. | 비공개, 운영진 공개, 회원 공개, 완전 공개 |
| 그룹 북마크 | 회원이 그룹 자체를 관심 대상으로 등록하는 것. 기록 보관과 구분한다. | `isBookmarked` |

## 2. 페이지 구성과 탭

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 내비게이션 바 | 페이지 맨 위에 고정되는 사이트 공통 메뉴 영역. 그룹 탭바와 구분한다. | `NavigationBar` |
| 탭바 | 그룹 페이지 왼쪽에서 탭 아이콘을 선택하는 세로 영역. | `TabBar` |
| 대시보드 | 탭바와 선택한 탭의 내용을 담는 패널을 묶은 영역. | `Dashboard` |
| 탭 패널 | 선택한 탭의 내용이 표시되는 대시보드 내부 영역. 카드 창과 구분한다. | `Dashboard`의 콘텐츠 영역 |
| 칸반 보드 | 리스트와 카드를 가로로 배치해 그룹 활동을 정리하는 영역. | `KanbanBoard` |
| 가용 창 영역 | 내비게이션 바와 펼쳐진 대시보드 등의 공간을 제외하고, 창 레이어가 배치될 수 있는 영역. 브라우저 전체 크기와 구분한다. | `WindowLayer`의 측정된 너비·높이 |
| 딤 배경 | 창 바깥에 표시되는 반투명 배경. 창 내부 배경이나 페이지 배경과 구분한다. | `overlayDim` |

탭 이름과 내부 식별자는 다음과 같다. 화면 이름을 바꾸더라도 내부 식별자와 같은 개념인지 구분한다.

| 화면 이름 | 내부 식별자 | 의미 |
| --- | --- | --- |
| 정보 | `info` | 그룹 정보와 통계를 조회하는 탭. |
| 멤버 | `member` | 그룹 멤버를 조회하고 관리하는 탭. |
| 채팅방 | `discord` | 그룹의 Discord 채팅방을 사용하는 탭. |
| 저장소 | `repository` | 연결된 코드 저장소를 조회하는 탭. |
| 활동공개 | `exposure` | 포트폴리오 발행과 활동보고 제출을 다루는 탭. 활동보고 탭이라고 부르는 경우도 이 탭을 뜻한다. |
| 카드검색 | `search` | 카드와 기록을 검색하는 탭. |
| 활동로그 | `log` | 그룹에서 발생한 활동 내역을 조회하는 탭. |
| 그룹아카이브 | `archive` | 삭제된 카드, 개인이 보관한 기록과 임시저장 접근을 제공하는 탭. |
| AI 채팅 | `aiChat` | AI 기능을 위한 탭. 현재는 안내만 표시한다. |
| 개발 | `development` | 개발 환경에서 목업 상태를 조정하는 탭. |
| 설정 | `settings` | 그룹 설정과 개인설정을 다루는 탭. |

## 3. 리스트·카드·기록

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 리스트 | 칸반 보드에서 카드들을 담는 단위. 기록 목록을 뜻하는 일반적인 목록과 구분한다. | `KanbanListDto` |
| 카드 | 하나의 주제나 작업을 나타내며 여러 기록을 담는 단위. 카드를 표시하는 창 자체와 구분한다. | `KanbanCardDto` |
| 카드 제목줄 | 카드 창 본문에서 카드 제목과 기록하기 버튼 등이 표시되는 줄. 스크롤하면 위에 붙는 영역이다. | `titleSection` |
| 제목 요소 | 카드 제목줄 안의 제목 텍스트 또는 제목 입력 요소. 제목줄 전체와 구분한다. | `title`, `titleInput` |
| 카드 설명 | 카드 자체에 붙는 설명. 개별 기록 본문과 구분한다. | `description` |
| 커버 이미지 | 카드 상단에 대표 이미지로 표시하는 이미지. 기록 본문 안의 이미지 첨부와 구분한다. | `coverImageUrl` |
| 라벨 | 카드에 붙이는 색상 표시. 탭이나 버튼에 쓰이는 일반적인 텍스트 라벨과 구분한다. | `labels`, `CardLabelDto` |
| 담당자 | 특정 카드를 담당하도록 지정한 회원. 카드 작성자와 그룹장과 구분한다. | `assigneeUserId`, `assigneeName` |
| 기록 | 카드에 작성하는 개별 게시물. 작성자, 본문, 시각과 상태를 가진다. | `RecordDto` |
| 기록 본문 | 기록의 실제 내용. 카드 전체 HTML, 작성자·시각·조작 버튼 등 기록 바깥 정보와 구분한다. | `content` |
| 기록 타입 | 본문을 어느 뷰어로 표시할지 구분하는 값. 카드 단위가 아니라 기록 단위로 정해진다. | `type: "tiptap" \| "legacy"` |
| Tiptap 기록 | 현재 블록 에디터와 뷰어가 다루는 기록. 현재 API의 본문은 HTML 문자열이며, Tiptap이라는 이름만으로 JSON 저장을 뜻하지 않는다. | `type: "tiptap"` |
| 레거시 기록 | 기존 SIGHT에서 작성된 HTML 본문을 별도 레거시 뷰어로 표시하는 기록. 기존 서버의 카드 전체 HTML 응답과 구분한다. | `type: "legacy"`, `LegacyViewer` |
| 첨부파일 | 기록 또는 채팅 메시지에 포함된 파일. 이미지·영상·음원처럼 본문 안에서 표시하는 경우와 다운로드 링크로 제공하는 경우가 있다. | 본문 리소스, 채팅 `attachments` |
| 이어받기 | 다른 카드와의 연결을 통해 그 카드의 기록을 이어서 조회하는 관계. 기록 자체를 현재 카드로 옮기는 기록 이동과 구분한다. | `inheritedFrom` |
| 기록 이동 | 기존 기록이 속한 카드를 다른 카드로 바꾸는 조작. | `moveGroupRecord` |

같은 카드 안에 Tiptap 기록과 레거시 기록이 함께 존재할 수 있다. 뷰어는 각 기록의 타입에 따라 선택한다.

## 4. 창과 배치

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 창 | 칸반 보드 위에서 카드, 기록 편집 또는 파일 등의 콘텐츠를 표시하는 상자. 브라우저 창이나 탭 패널과 구분한다. | `Window` |
| 창 레이어 | 창의 배치, 상태 적용, 애니메이션과 바깥 클릭을 관리하는 영역. | `WindowLayer` |
| 카드 창 | 카드 제목·설명과 기록 목록을 조회하는 창. | `CardWindow` |
| 기록 편집 창 | 새 기록 작성 또는 기존 기록 수정을 위한 창. 기록 작성 창도 같은 뜻으로 사용한다. | `EditWindow` |
| 파일 창 | 파일 내용을 표시하는 창. | `FileWindow` |
| 창 헤더 | 창 상단의 제목·라벨 표시와 조작 버튼이 있는 영역. 창이 내려간 상태에서 화면 하단에 남아 보이는 부분이다. 카드 본문의 제목줄과 구분한다. | `.js-window-header` |
| 창 헤더 빈 부분 | 헤더 안에서 버튼·링크 등 별도의 조작 요소가 아닌 부분. 헤더 조작 버튼까지 포함하는 표현으로 사용하지 않는다. | 헤더 배경 클릭 영역 |
| 창 조작 버튼 | 내리기·올리기, 펼치기, 좌우 교환·보내기, 닫기 버튼. | `Window`의 헤더 버튼 |
| 슬롯 | 창 또는 빈 자리가 배치되는 위치. 슬롯과 그 안에 표시하는 콘텐츠는 서로 다른 개념이다. | `PhysicalSlot`, `SlotValue` |
| 싱글 모드 | 창을 하나의 전체 슬롯에 배치하는 모드. 실제 창 개수가 하나라는 것만으로 싱글 모드가 되는 것은 아니다. | `LayoutState.kind: "Single"` |
| 듀얼 모드 | 좌우 두 슬롯을 사용하는 모드. 한쪽이 비어 있어도 듀얼 모드이다. | `LayoutState.kind: "Dual"` |
| 메인창 | 듀얼 모드에서 실제 너비가 더 넓은 쪽의 창 역할. 너비가 같으면 왼쪽이 메인이다. 포커스된 창이라는 뜻은 아니다. | `role: "main"` |
| 서브창 | 듀얼 모드에서 메인 반대쪽의 창 역할. 보조창과 같은 뜻으로 사용한다. | `role: "sub"` |
| 빈 슬롯 | 콘텐츠가 없는 듀얼 모드의 자리. 내려간 창과 구분한다. 빈 윈도우도 이 개념을 뜻한다. | `"Empty"` |
| 창 역할 | 싱글·메인·서브라는 논리적 구분. 왼쪽·오른쪽이라는 물리적 위치와 구분한다. | `WindowRole` |
| 메인 위치 | 듀얼 모드에서 어느 물리적 방향이 메인 역할인지 나타내는 값. | `mainSide` |
| 분할 비율 | 듀얼 모드에서 두 창의 너비를 나누는 사용자 선택값. 왼쪽 비율로 저장하며 실제 표시 너비에는 최소 폭 제한이 적용된다. | `splitRatio`, 예: `0.7`은 왼쪽 70% |
| 분할 핸들 | 두 슬롯 사이에서 드래그해 분할 비율을 조절하는 영역. | `resizeHandle` |
| 창 ID | 화면에 열린 창 인스턴스를 구현상 내부적으로 구분하기 위한 식별자. 카드·기록 ID나 메인·서브 역할과 구분한다. | `windowId`, `windowIds` |
| 콘텐츠 키 | 창에 어떤 콘텐츠를 표시할지 나타내는 식별자. 같은 콘텐츠를 표시하는 창도 창 ID는 다를 수 있다. | 카드 ID 문자열, `edit:...`, `file:...` |

창의 개수, 배치 모드, 역할, 물리적 위치, 내려감 여부는 별개의 개념이다. 예를 들어 오른쪽에 작은 창 하나만 있고 왼쪽이 비어 있다면, 듀얼 모드의 서브창 하나와 빈 메인 슬롯일 수 있다.

## 5. 창 조작과 상태 복원

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 열기 | 창 레이어에 콘텐츠를 표시할 창을 배치하는 조작. 새 인스턴스를 만들거나 기존 창을 교체할 수 있다. | `openWindow` |
| 닫기 | 창을 레이어에서 제거하는 조작. 내리기와 구분한다. | `close` |
| 내리기 | 열린 창을 하단 헤더만 남도록 접는 조작. 최소화와 같은 뜻이다. 창은 계속 존재한다. | `minimize` |
| 올리기 | 내려간 창을 원래의 싱글 또는 듀얼 슬롯 높이로 되돌리는 조작. | `raise` |
| 펼치기 | 현재 내림 상태와 관계없이 창을 항상 싱글 모드의 올림 상태로 만드는 조작. 반대쪽 창이 있으면 닫는다. 올리기는 기존 배치 모드를 유지한다는 점에서 구분한다. | `expand` |
| 창 교환 | 양쪽 창의 콘텐츠를 서로 바꾸는 조작. 좌우 위치의 내려감 상태는 각 위치에 유지한다. | `switch` |
| 좌우로 보내기 | 창을 선택한 왼쪽 또는 오른쪽으로 옮기는 조작. 전체 너비로 표시되던 창은 너비를 줄여 한쪽에 표시하고, 이미 한쪽에 있는 창은 비어 있는 반대쪽으로 옮긴다. 창의 내림·올림 상태는 유지한다. | `sendToSide`, `moveToEmptySide` |
| 창 교체 | 기존 창 자리에 다른 콘텐츠를 표시하도록 바꾸는 것. | 기록 편집 창의 출발 카드 창 교체 등 |
| 상태 전이 | 현재 상태와 조작을 바탕으로 다음 창 배치를 계산하는 과정. | `applyWindowAction`, 상태 매핑 |
| 스냅샷 | 특정 시점의 창 배치·콘텐츠·창 ID·분할 비율·메인 위치를 묶은 상태. | `WindowSnapshot` |
| 상태 적용 | 목표 스냅샷과 현재 상태의 차이를 반영해 창 유지·제거·이동과 애니메이션을 처리하는 과정. | `applySnapshot` |
| 커밋 | 목표 상태를 화면에 적용하고 URL·브라우저 히스토리에도 반영하는 처리. 드래그 중 화면 미리보기와 구분한다. | `commit` |
| URL 해시 | URL의 `#` 뒤에 표시하는 공유 가능한 창 배치와 콘텐츠 정보. | `windowHash` |
| 브라우저 히스토리 | 뒤로가기·앞으로가기로 복원할 내비게이션 내역. 그룹 활동로그와 구분한다. | `location.state.sightWindowHistory` |
| 히스토리 복원 | URL과 히스토리 정보로 목표 스냅샷을 만들고 현재 화면에 적용하는 과정. 사용자 조작을 다시 실행하는 것과 구분한다. | `syncFromHash` |

## 6. 삭제·보관·임시저장

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 카드 비활성화 | 카드를 보드에 남겨두면서 편집 등의 조작을 제한하는 상태 변경. 삭제와 구분한다. | `disabled` |
| 카드 삭제 | 카드를 보드에서 제외하고 그룹아카이브에서 복구할 수 있도록 처리하는 조작. 현재 API 함수 이름의 archive는 이 삭제를 뜻한다. | `archiveGroupCard`, `ArchivedCardDto` |
| 기록 삭제 | 기록에 삭제 상태를 부여하는 조작. 개인 보관과 구분한다. | `archiveGroupRecord`, `deleted` |
| 복구 | 삭제된 카드 또는 기록을 다시 사용할 수 있도록 되돌리는 조작. 창 올리기·히스토리 복원과 구분한다. | `restoreGroupCard`, `restoreGroupRecord` |
| 기록 보관 | 회원이 기록을 개인 보관 목록에 추가하는 조작. 원래 카드에서 기록을 제거하지 않는다. | `saveGroupRecord`, `SavedRecordDto` |
| 보관 해제 | 회원의 개인 보관 목록에서 기록을 제거하는 조작. 기록 자체의 삭제가 아니다. | `removeSavedGroupRecord` |
| 삭제일 | 카드가 삭제된 시각. 생성일과 구분한다. | `deletedAt` |
| 보관일 | 회원이 기록을 개인 보관한 시각. 기록 작성일과 구분한다. | `savedAt` |
| 초안 | 아직 최종 제출하지 않은 기록 편집 내용. 이미 제출된 기록과 구분한다. | 기록 편집 상태 |
| 임시저장 | 기록 초안을 나중에 이어서 편집할 수 있도록 저장하는 것. 개인 기록 보관과 구분한다. | `AutosaveApi`, `useRecordDraft` |

그룹아카이브는 여러 기능을 모은 탭 이름이다. 문서에서는 아카이브라는 단어만으로 카드 삭제, 기록 보관, 임시저장 중 어느 조작인지 표현하지 않는다.

## 7. 활동공개와 저장소

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| 포트폴리오 포함 | 특정 카드를 포트폴리오 공개 대상으로 선택하는 것. 그룹 포트폴리오 발행과 구분한다. | 카드의 `portfolio` |
| 포트폴리오 발행 | 그룹 포트폴리오를 외부에서 조회할 수 있도록 공개하는 조작. | `hasPublishedPortfolio`, `publishGroupPortfolio` |
| 활동보고 | 그룹의 활동 결과를 제출하는 항목. 발표 유형과 보고서 유형을 포함한다. | `ActivityReportDto` |
| 활동보고 파일 | 활동보고에 제출하는 파일. 카드 커버 이미지나 기록 첨부파일과 구분한다. | `reportFileUrl`, `fileUploadId` |
| 접수 기간 | 현재 활동보고를 제출할 수 있는 세미나 단위의 접수 정보. 개별 그룹이 임의로 정하는 기록 기간과 구분한다. | `OpenSeminarCohortDto`, `seminarId` |
| 저장소 | 그룹에 연결된 Git 저장소. 브라우저 저장소나 QueryClient 캐시와 구분한다. | `repositoryUrls` |
| 브랜치 | Git 저장소의 개발 분기. | `RepoBranch` |
| 커밋(Git) | Git 저장소의 변경 이력을 나타내는 항목. 창 상태 커밋과 구분한다. | `RepoCommit` |

## 8. 데이터와 설정

| 용어 | 정의 | 현재 코드 또는 표기 |
| --- | --- | --- |
| API 객체 | 화면에서 호출하는 기능별 비동기 함수의 진입점. 요청과 응답 변환을 담당한다. | `KanbanApi`, `GroupExposureApi` 등 |
| DTO | API 함수의 입력·출력 데이터 구조. 현재 목업의 DTO가 확정된 서버 계약을 뜻하는 것은 아니다. | `RecordDto`, `GroupInfoDto` 등 |
| 목업 | 실제 백엔드 구현 대신 개발 중의 응답과 변경 동작을 제공하는 구현. | `dev/mockApi` |
| 쿼리 캐시 | 서버 조회 결과를 화면에서 공유하기 위한 메모리상의 저장 공간. 영구 저장소와 구분한다. | TanStack Query의 `QueryClient` |
| 페이지 상태 | 현재 페이지 사용 중 유지하는 UI 상태. 탭 선택, 필터, 파일 표시 방식 등의 상태를 포함하며 모두 하나의 객체에 모여 있다는 뜻은 아니다. | 컴포넌트 상태, `GroupDetailPageState` |
| 개인설정 | 페이지를 닫거나 다른 그룹으로 이동해도 유지할 사용자 설정. 현재 로컬 저장 대상은 듀얼창 사용 여부와 분할 비율이다. | `groupPagePreferences` |
| 로컬스토리지 | 브라우저에 개인설정 등을 저장하는 저장소. Git 저장소와 구분한다. | `localStorage`, `sight:group-page-preferences` |
| 업로드 링크 | 파일을 업로드할 위치와 업로드 식별자 등을 반환하는 정보. 파일을 조회하는 주소와 구분한다. | `url`, `fileUploadId` |
| 파일 조회 주소 | 업로드된 파일을 표시하거나 다운로드할 때 사용하는 주소. 업로드 요청을 보내는 주소와 구분한다. | `fileUrl`, `reportFileUrl` |
